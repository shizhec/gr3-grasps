# 仓库与两端部署

服务器和机器人计算机使用同一份 `gr3_grasping` Git 仓库。个人电脑可以保留一份用于查看、修改和同步代码，运行时不必参与。以下命令在仓库根目录执行；示例远程地址、SSH 用户和服务器地址需替换。

## 仓库内容

| 目录或文件 | 内容 |
|---|---|
| `src/gr3_grasping/deployment/` | 网络协议、服务器推理入口、本机执行器、设备适配 |
| `src/gr3_grasping/` | 点云、定位、抓姿、MuJoCo、cuRobo 等实现 |
| `configs/` | 可提交的仿真配置与默认关闭动作的部署示例 |
| `requirements/robot*.txt` | 机器人侧依赖；不安装 Torch、CUDA 或 MuJoCo |
| `pyproject.toml`, `uv.lock` | 服务器基础环境与 Python 依赖锁定 |
| `assets.lock.json`, `scripts/setup_*.sh` | 第三方模型及算法源码的固定提交和重建入口 |
| `scripts/`, `tests/`, `docs/` | 数据准备、验证、历史实验与部署说明 |
| `.github/workflows/ci.yml` | 上传 GitHub 后执行 CPU 测试与轻量机器人通信检查 |

虚拟环境、`third_party/`、`outputs/`、`assets/generated/` 不进入 Git。现场配置使用 `configs/deployment_site.yaml`，相机实测标定放入 `calibration/`，令牌保留在环境变量或本机 `.env`；这些路径已忽略。`configs/deployment_mvp.yaml` 与 `configs/deployment_oak.example.json` 是模板，不能当作实机标定。

项目按源码检出部署，保留仓库中的 `configs/` 和 `scripts/`，再做可编辑安装；当前不支持仅复制一个 wheel 后独立运行全部功能。

## 机器人端：轻量安装

先克隆仓库：

```bash
git clone YOUR_GIT_URL gr3_grasping
cd gr3_grasping
```

使用厂商 SDK 兼容的 Python **3.10 或更高版本**。如果 SDK 已装在该 Python 环境中，可以创建继承其包的独立环境；如果 SDK 由厂商脚本配置，则先加载厂商环境，保留其 `PYTHONPATH`、`LD_LIBRARY_PATH`。

```bash
# 将 python3 替换为现场 SDK 实际使用的 Python。
python3 -m venv --system-site-packages .venv-robot
.venv-robot/bin/python -m pip install -r requirements/robot.txt
.venv-robot/bin/python -m pip install --no-deps -e .
.venv-robot/bin/gr3-deploy probe
.venv-robot/bin/python scripts/smoke_deployment.py --output outputs/first_transport
```

通信演示会自行生成小型人工 RGB-D/关节输入、临时令牌和空闲端口，启动两个独立进程，运行静止轨迹并收取回执。它不访问相机和 SDK，不推理抓姿，也不测试实际抓取。每次换一个新的输出目录。成功时 `client/robot_report.json` 包含 `trajectory_completed: true`、`hardware: false`、`grasp_success: null`。

需要直接连接 OAK 时再安装：

```bash
.venv-robot/bin/python -m pip install -r requirements/robot-oak.txt
```

Aurora、FourierDDS 与消息类型使用实际交付包，未写入公共 PyPI 安装列表。机器人依赖采用兼容版本范围，最终在现场按厂商 SDK 锁定；服务器的 `uv.lock` 不用于机器人环境。不要在机器人端执行完整 `uv sync`，它会安装仿真依赖。

## 服务器端：仿真与 GPU 推理

基础 CPU/仿真环境使用 Python 3.11 和 `uv`：

```bash
python3 scripts/fetch_assets.py
uv sync --locked --extra dev
.venv/bin/pytest -q
.venv/bin/gr3-grasp simulate --no-video --output outputs/first_simulation
```

无显示器环境需要 EGL/OpenGL 运行库。语言检测和 M2T2 为可选项，安装方式见 README 对应章节。需要 GPU cuRobo 时另建独立环境，脚本固定 Torch/CUDA 和 cuRobo 源码版本：

```bash
bash scripts/setup_curobo.sh
.venv-curobo/bin/gr3-deploy probe
```

**只克隆代码并不能立刻重现当前服务器的完整 Dexonomy 杯子推理。** 还需要 `configs/deployment_mvp.yaml` 指定的 v3 候选、`configs/dexonomy_gr3_mug.yaml` 指定的 v2 手部元数据，以及候选引用的场景/物体导出文件。它们是离线生成数据，放在被忽略的 `outputs/`。候选内还包含生成时的绝对路径，不能仅复制两个 `.npy` 到另一台服务器便认为已完成迁移。当前开发服务器保留完整输入，不受 Git 整理影响；新推理服务器需按 [Dexonomy 接入说明](Dexonomy_FDH6接入.md) 重新导出、生成，或同时迁移并重新绑定完整数据路径。机器人端无需这些数据。

## 现场配置和两端启动

两端各自复制配置模板并填写该端参数。不要提交共享令牌和实测标定：

```bash
mkdir -p calibration
cp configs/deployment_mvp.yaml configs/deployment_site.yaml
cp configs/deployment_oak.example.json calibration/oak.json
```

将 `camera.calibration_file` 指向 `calibration/oak.json`，填写实际标定与 SDK 映射。保持运动开关关闭，直到现场验证。服务器端推理范围和机器人端执行检查分别受各自配置约束，修改一端不会替另一端确认。

在服务器和机器人端分别设置同一个随机令牌。可以用 `python3 -c 'import secrets; print(secrets.token_urlsafe(32))'` 生成一次，然后安全地配置到两端。

```bash
# 服务器端
export GR3_DEPLOY_TOKEN='REPLACE_WITH_THE_SAME_RANDOM_TOKEN'
.venv-curobo/bin/gr3-deploy --config configs/deployment_site.yaml server \
  --output outputs/site_server_run01
```

```bash
# 机器人端独立终端：将 TCP 通道通过 SSH 转发到服务器。
ssh -N -L 5557:127.0.0.1:5557 user@server
```

```bash
# 机器人端：采集后先请求规划，不打开执行适配器。
export GR3_DEPLOY_TOKEN='REPLACE_WITH_THE_SAME_RANDOM_TOKEN'
.venv-robot/bin/gr3-deploy --config configs/deployment_site.yaml record \
  --output outputs/site_observation01.msgpack
.venv-robot/bin/gr3-deploy --config configs/deployment_site.yaml client \
  --observation outputs/site_observation01.msgpack --output outputs/site_plan01
```

`record` 需要真实标定及可读取的 SDK/手部状态，当前模板故意不能直接通过。实际执行入口、每次重新观察要求和现场适配表见 [真机最小运行版本](真机最小运行版本.md)。

## 版本同步和离线复制

现场前在两端执行 `git rev-parse HEAD`，确认提交号一致。更新前先检查本地修改，使用 `git pull --ff-only` 更新，并在对应环境重新做可编辑安装；现场配置保留本机。SDK 版本、设备型号和标定信息单独记录。

没有远程 Git 服务时，可在有提交的源仓库生成 Git bundle，只打包 `main` 分支的已提交代码和历史，不包含模型、录像或本地配置：

```bash
git bundle create outputs/gr3_grasping.bundle main HEAD
git bundle verify outputs/gr3_grasping.bundle
```

把 bundle 复制到机器人后克隆：

```bash
git clone /absolute/path/gr3_grasping.bundle gr3_grasping
cd gr3_grasping
```

bundle 的 `origin` 初始指向本地文件。得到远程地址后，在两端用 `git remote set-url origin YOUR_GIT_URL` 更新；如果尚无 `origin`，用 `git remote add origin YOUR_GIT_URL`，再推送 `main`。

## 验证范围

GitHub CI 在没有第三方资产和 GPU 的环境运行基础测试；需要官方模型、Dexonomy 或 CUDA 的测试会按前置条件跳过。另一个独立任务只装机器人依赖，验证探测与两进程通信，不安装 MuJoCo/Torch/cuRobo。CI 通过不等于真机抓取通过。
