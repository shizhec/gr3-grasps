# GR3 头部扫描与观测点云融合

仿真入口增加 `--head-scan`。在官方 GR3 头部相机安装位置采集初始帧，先用 RGB-D 识别目标，再根据观测目标中心计算头部朝向，在中心左右约 0.30 rad 处增加视角。总计最多四帧；只通过头部关节位置伺服运动，不移动相机挂载或物体。扫描后头部恢复初始姿态，再规划并执行一次抓取。

```bash
cd gr3_grasping
.venv/bin/gr3-grasp simulate --config configs/scanned_candy.yaml \
  --backend m2t2 --arm right --head-scan --no-video \
  --output outputs/my_head_scan
```

也可以在 YAML 中设置，单次仿真与批测使用同一实现：

```yaml
head_scan:
  enabled: true
  yaw_offsets_rad: [-0.30, 0.0, 0.30]
  max_joint_speed_rad_s: 0.35
  settle_s: 0.35
  tracking_tolerance_rad: 0.015
  voxel_size_m: 0.002
  model_context_margin_m: 0.12
  association_radius_m: 0.006
  min_overlap_fraction: 0.08
```

头部命令受导入模型的关节限位约束，保留 0.001 rad 边距；五次平滑轨迹控制命令速度，实际位置跟踪、速度与恢复误差均保存。当前模型偏航范围约 ±80°，俯仰为 −30° 至 +8.5°；正俯仰对应低头。原始姿态已接近最大低头角，因此不能靠增大低头命令把桌面移到画面中央。仿真运动不是经过真机验证的动作指令。

## 融合和目标关联

每次等伺服稳定后同步读取 RGB-D、仿真时间和当时的 `T_world_camera`。用各帧自己的内外参反投影到同一世界坐标系，在原有工作区内融合桌面与物体观测；2 mm 体素内平均位置和颜色。新视角的目标按与初始目标点云的空间重叠关联，拒绝不匹配的机器人前景。目标关联不读取物体 ID、真值位姿、网格或 MuJoCo 分割缓冲区。

M2T2 接收融合后的观测场景，仍使用原始 16384 点、相同阈值、相同权重、相同手部映射和控制。默认在融合目标的观测 XY 边界外保留 12 cm 桌面/障碍物上下文，降低大面积桌面稀释目标采样的影响；不改变物体的世界位置、尺寸或 Z 值。完整融合场景仍保存在文件中，实际采样输入另存于 `m2t2_raw.npz`。`model_context_margin_m: null` 关闭该裁剪。GraspGen/几何后端可使用融合目标，但本轮物理抓取对照使用 M2T2。`target_cloud.npz` 的相机坐标以初始帧为参考；融合后的部分点可能落在初始视场之外。顶层 `target_mask.png` 仍对应初始图像，各视角的掩码分别保存。

扫描假设桌面和物体静止。世界系配准当前使用理想运动学外参，未实现真机时钟同步、外参修正或动态目标跟踪。单纯转头产生的相机平移只有数厘米，增加的占据体素同时反映观测密度和少量新可见表面，不能当作物体完整表面重建比例；无法补出所有背面、底面或被遮挡区域。初始帧需要先看见并识别目标，尚未实现目标完全离开视野时的主动搜索。

## 输出

| 路径 | 内容 |
|---|---|
| `head_scan/views.png` | 四视角拼图，绿色标出每帧目标 |
| `head_scan/frame_00.npz` 等 | 各帧 RGB-D、内外参和时间戳 |

| `head_scan/fused_cloud.npz` | 世界系融合场景/目标点云与颜色 |
| `head_scan/scan.json` | 命令/实测关节角、限位、跟踪、相机基线、体素数量和关联结果 |
| `m2t2_metadata.json` | 融合输入标记、固定权重信息、推理输出数量和兼容修正记录 |

即使 M2T2 无候选或规划失败，已经完成的扫描文件也会保留。

## M2T2 目标筛选错误与独立对照

检查 [官方 M2T2 源码](https://github.com/NVlabs/M2T2/blob/master/m2t2/m2t2.py) 时发现：

```python
# 原表达式：布尔值和整数位运算，非空掩码只有奇数点数能通过。
(score > cfg.object_thresh) & mask.sum(dim=1) > 0
# 修正：同时满足置信度阈值与掩码非空。
(score > cfg.object_thresh) & (mask.sum(dim=1) > 0)
```

`m2t2_compat.py` 仅在加载的模型实例上替换这一个表达式，核对旧表达式唯一存在；不会修改下载的源码、模型结构、训练参数或阈值。修正前后的函数 SHA-256 与表达式记在模型元数据中。默认启用，可用 `--legacy-m2t2-filter` 或配置 `m2t2.fix_object_mask_filter: false` 重现旧行为。测试覆盖空掩码、奇/偶点数以及低置信度。

历史 `outputs/benchmark10_com` 的 2/30 是旧筛选实现的完整链路结果；19 次无候选不能据此解释为模型没有识别能力。原始物理执行证据与分母保留，不覆盖历史文件。

为区分筛选修复与头部扫描，采用三个独立目录：旧筛选单视角、修正筛选单视角、修正筛选头部扫描。每组仍为相同十物体、三个朝向、每场景一次物理执行，成功标准保持质心提起至少 10 cm 并稳定保持 2 秒及对向承力接触。失败全部计入分母。

首轮直接融合后，单视角对照为 3/30 成功、直接融合为 1/30；虽然目标占据体素增加，16384 个输入中的目标邻域点占比中位数却从 3.47% 降至 2.22%（按距观测目标点云 3 mm 内计数）。据此新增一轮所有物体统一使用 12 cm 上下文裁剪的测试。首轮失败结果保留，不能将点云体素增加解释为抓取成功率提升，也不能把后续配置探索当作独立未知物体上的泛化评估。

```bash
# 修正筛选后的单视角对照
.venv/bin/python scripts/benchmark_objects.py \
  --output outputs/my_filter_fixed --jobs 2
# 相同修正 + 头部扫描
.venv/bin/python scripts/benchmark_objects.py --head-scan \
  --output outputs/my_head_scan_benchmark --jobs 2
# 复现首轮不裁剪上下文的扫描对照
.venv/bin/python scripts/benchmark_objects.py --head-scan --head-context-margin-m 0 \
  --output outputs/my_uncropped_head_scan --jobs 2
# 复现历史旧筛选单视角
.venv/bin/python scripts/benchmark_objects.py --legacy-m2t2-filter \
  --output outputs/my_legacy_baseline --jobs 2
```

每次批测同时保存有效清单哈希、实现文件哈希和逐场景配置。`--head-scan` 目前只在仿真执行头部动作；真机入口保持只读。

## 完成的对照结果

| 配置 | 成功 / 全部场景 | 无有效候选 | 路径不可行 | 未稳定提起/滑落 |
|---|---:|---:|---:|---:|
| 历史旧筛选、单视角 | 2/30 | 19 | 5 | 4 |
| 修复筛选、单视角 | 3/30 | 5 | 11 | 11 |
| 修复筛选、四视角直接融合 | 1/30 | 5 | 10 | 14 |
| 修复筛选、四视角融合、12 cm 上下文 | 3/30 | 0 | 13 | 14 |

30 个扫描场景均取得 4 个可关联视角，目标占据体素增幅中位数为 57.3%，相机基线为 5.86–7.21 cm。裁剪后输入目标邻域点占比中位数为 8.15%。这改善了观测与候选覆盖，整体成功率仍与修复后的单视角持平。不能将 6.7% 到 10% 的变化全部归因于头部扫描。

扫描加裁剪组成功场景为糖果盒 90°、蜡笔盒 90°、小瓷碗 45°，保持期质心最小升高分别为 14.10、14.90、14.20 cm，均保持 2 秒，承力对向接触比例均为 100%。与单视角组的成功场景有所变化，未做按结果选择两组较优候选的执行策略。

数据分别保存在 `outputs/benchmark10_com`、`outputs/benchmark10_filter_fixed`、`outputs/benchmark10_head_scan`、`outputs/benchmark10_head_scan_context`。完整汇总为 `outputs/head_scan_comparison/report.md` 和 `comparison.json`。对照确认：历史与修复组的 30 组采样输入逐元素相同；直接融合与裁剪组的 30 组融合点云逐元素相同。

实际头部扫描回放为 `outputs/head_scan_demo/head_scan.mp4`，附带四视角拼图、同尺度点云对比与可导入 PLY。27 项回归测试、依赖锁及编译检查通过。下一步瓶颈是 FDH-6 接触位姿/预成形、可达候选选择和闭手反馈。
