# GR3 相机抓取方案与官方资源核实

核实日期：2026-10-20。以下“官方”指傅利叶、NVIDIA、Luxonis 或模型作者发布的资源。

## 1. 官方仿真和模型是否存在

| 资源 | 核实结果 | 本项目用法 |
|---|---|---|
| [FFTAI/Wiki-GRx-Models](https://github.com/FFTAI/Wiki-GRx-Models) | 提供 `GRX/GR3/gr3v2_1_1`，有基本 URDF、dummy hand URDF、mesh、MJCF；另外有独立 Fourier 6DOF 手 URDF | 已下载、固定提交、实际从 URDF 导入 MuJoCo |
| [FFTAI/fourier_aurora_sdk](https://github.com/FFTAI/fourier_aurora_sdk) | 支持 GR3，`sim/mujoco` 提供基于 LCM 的仿真桥，`python/example/gr3` 提供运动客户端示例 | 已下载供接口核对；未启动依赖机器人运行时的 Aurora/LCM 服务 |
| [FFTAI/fourier_lab](https://github.com/FFTAI/fourier_lab) | 基于 Isaac Lab 的训练代码，包含 GR3 多个模型修订目录和 URDF→USD 导入说明，主要任务是运动控制 | 后续大规模接触抓取/随机化的候选平台；本阶段没有安装 Isaac Sim |
| [GR3 官方仿真与训练页面](https://support.fftai.com/en/gr3/development/simulation-and-training) | 页面仍标注建设中 | 不能将页面当成完整的 GR3 抓取教程 |
| [GR-Sensor 文档](https://support.fftai.com/en/gr3/modules/gr-sensor) | 当前公开契约主要是 IMU/触觉；相机/雷达流接口仍标注建设中 | 没有编造相机 DDS 订阅接口，先使用统一 RGB-D 帧和可选设备驱动 |
| [GR-EndEffector 文档](https://support.fftai.com/en/gr3/modules/gr-endeffector) | 描述 FDH-6、FDH-12，以及手部命令、状态、触觉 DDS 主题 | 真机手控制需按交付的手型号、SDK/固件核对 |

`gr3v2_1_1` 等是公开机械模型的内部命名/修订号，不代表可以直接据此划分商品版本。优先使用用户交付包中的 URDF，确认匹配后再替换仿真配置。独立 6DOF 手模型的存在不意味着它就是这台 GR3 的手。

## 2. 建议的系统结构

```text
仿真 camera_link RGB-D / 真机原生相机
                 ↓
统一 RGBDFrame（RGB、米制深度、K、动态外参、时间戳）
                 ↓
Grounding DINO 文字目标框 → 深度前景（后续加入 SAM2 处理堆叠）
                 ↓
目标点云 + 场景障碍点云
                 ↓
M2T2 / GraspGen 抓取候选 → 源夹爪基座转接触中心 → GR3 手掌/手指适配
                 ↓
择臂 → 有界 IK → 自碰撞/桌面/物体碰撞检查 → 轨迹
                 ↓
预抓取 → 接近 → 闭手 → 触觉/电流判断 → 提起 → 成功检测
                 ↓
MuJoCo 执行器 / 机器人侧 Aurora + EndEffector 执行器
```

本项目已实现 FDH-6 的预抓取、接近、闭手、提起和保持评估，红色方块完整流程已通过，包含不闭手失败对照。场景碰撞使用场景模型，尚未从真实深度重建障碍物。真机运动执行器尚未实现。相机安装位姿取自 URDF 的 `camera_link`；FOV、光学中心和 TCP 暂用显式配置的假设值，不能作为真机标定。

## 3. MuJoCo 与学习模型

MuJoCo 可以直接导入官方 URDF，安装小，CPU 上即可运行关节控制和接触物理。本机 RTX 5090 当前几乎被三个已有任务占满，先使用软件渲染与 CPU 感知可以立即验证坐标和控制链路。初始操作固定基座、固定站姿，不同时解决行走、全身平衡和物体抓取三个问题。后续需要大量物体、材料/光照/接触随机化、并行评估时再增加 Isaac Lab。

[GraspGen](https://github.com/NVlabs/GraspGen) 适合从部分物体点云生成多个 6D 抓取候选，官方也有独立 GPU 服务接口，便于机器人侧轻量客户端调用。项目保留该协议适配器，尚未运行其 GPU 权重。[M2T2](https://github.com/NVlabs/M2T2) 已接入官方网络和作者的固定版本权重，以 CPU 参考算子替代 CUDA PointNet++ 扩展；真实扫描糖果盒的完整抓取通过，药瓶仍失败。详见 [扫描资产与 M2T2](实物扫描与M2T2.md)。

GraspGen 的公开实现主要提供 Franka、Robotiq 2F-140 和吸盘权重，不能把夹爪候选直接当成 GR3 灵巧手的有效抓取。GraspGen 接口按 [官方夹爪坐标说明](https://github.com/NVlabs/GraspGen/blob/main/docs/GRIPPER_DESCRIPTION.md) 处理 +Z 接近方向、X 闭合方向和基座到接触点的深度偏移，转换为 GR3 TCP 候选。默认已验证的 FDH-6 抓取使用独立几何策略：从深度点云估计物体中心，使用灵巧手预成形与手掌开口方向的接近。GraspGen 的 FDH-6 抓取质量和 GPU 推理尚未验证；不能把源夹爪分数当作本手的质量分数。

Grounding DINO 已接入 CPU 可选环境；其目标框后接深度连通前景，可以处理当前分离摆放的桌面物体。堆叠、接触的多物体需加入实例掩码（例如 SAM2）、遮挡处理和重新观测。几何基线也保留，用于定位坐标错误及无需 GPU 的回归验证。

## 4. 实施阶段和验收

| 阶段 | 验收内容 | 当前状态 |
|---|---|---|
| A. 官方模型和相机 | 官方 GR3 实体外观、安装位姿 RGB-D、米制点云 | 已实现；真实相机内外参待标定 |
| B. 感知到预抓取 | 目标选择、候选、择臂 IK、路径碰撞、实际物理运动、结果视频 | 几何基线已实测；学习感知见运行报告 |
| C. GR3 手接触抓取 | 可动手模型、联动关节、指尖碰撞、闭合策略、重定向 | 按用户选择接入官方 FDH-6；每手 6 主动 + 5 联动；红方块闭手已验证 |
| D. 物体提起评估 | 无绑定/吸附作弊，物体持续提起超过 10cm、保持 2s、无滑落；按物体/视角统计成功率 | 已实现高度、对向接触及保持检查；红方块通过，不闭手对照失败；未完成多物体成功率统计 |
| E. 真实数据离线验证 | 原生相机采集、去畸变/深度对齐、动态外参、同步关节、点云与仿真叠合 | 有 NPZ 回放、可选 OAK 采集及 Aurora 只读入口；未硬件实测 |
| F. 真机闭环 | 机器人侧执行器、站立控制、限速、通信超时、闭手反馈、视觉/触觉提起检测 | 尚未实现 |

后续按 FDH-6 继续扩展物体和真机对接：

1. 核对交付版 GR3/FDH-6 与公开 URDF 的安装和关节映射。当前已使用官方脚本相同的腕部单位安装变换、每手 5 个 mimic 约束和官方网格凸包接触；力矩和伺服参数为显式仿真假设，需从交付 SDK 核实。
2. 将候选 TCP 转为手掌位姿并确定预成形；可先验证拇指与食指/中指对捏，再扩展包络抓取。GraspGen 提供候选，原生手负责接触验证与重排序；必要时使用对应手的数据重新训练或采用适合灵巧手的模型。
3. 扩展圆柱、球体、不规则物体、多尺寸和遮挡下的手指预成形、接触姿态重排序与失败恢复。当前连续路径、闭合、提起和失败判定已实现，但不会自动重新观测或重抓。
4. 接入原生相机真实帧，校正 RGB-D 内参、畸变、深度比例、相机到头部/基座外参及双臂 TCP，测量时延。
5. 以机器人实测关节状态初始化规划，把感知/候选推理放在服务器，Aurora 执行桥放在机器人本机。官方 [快速开始](https://support.fftai.com/en/gr3/getting-started/quick-start) 当前说明 Python 客户端不能直接从远端控制 Aurora。
6. 保持每阶段使用相同坐标约定和数据接口，加入深度噪声、外参误差、摩擦、质量、执行延迟随机化；在仿真统计通过后再验证真机。

“任意物体”的工程目标应理解为开放类别、可见、可达且满足手尺寸/载荷条件的物体。透明、反光物体可能没有可靠双目深度，严重遮挡、过大/过重或无法形成稳定接触的物体，需要额外观测或不同策略。物体识别能力和手部抓取能力分别验收。
