# 灵巧手抓取方法调研：面向 GR3 + FDH-6

调研日期：2026-10-21。依据论文、作者项目主页、官方仓库和自定义手教程；本文件是文献与代码接口调研，不表示已复现下列项目。当前项目实际跑通的学习模型仍是 M2T2。

后续已完成 Dexonomy 的 FDH-6 离线适配与十物体开发测试；修正联动积分后，筛选出的六个候选中四个完成独立手部提起，覆盖糖果盒与杯子，仍未接入全臂/相机执行。实现范围和对照验证见 [Dexonomy 接入说明](Dexonomy_FDH6接入.md)。

## 关键区别

灵巧手抓取常见的输出不只是一组末端位姿，还包括手指预成形、目标关节配置或连续动作。部分方法先产生手物接触关系，再通过手的运动学恢复手腕与手指姿态；另一些方法直接学习机械臂与手的连续控制。

面向当前 FDH-6，静态抓姿可表示为手腕六维位姿和六个主动手指关节；五个联动关节须遵循当前模型的 mimic 关系。不能把其他手的独立关节自由度直接搬过来。最终抓姿的静态质量、从初始状态能否无碰撞接近，以及闭手后能否稳定提起，是不同的验证问题。

## 1. 接触模板与物理优化

### Dexonomy（RSS 2025）

- 官方：[仓库](https://github.com/JYChen18/Dexonomy)、[项目主页](https://pku-epic.github.io/Dexonomy/)、[自定义手与接触模板教程](https://github.com/JYChen18/Dexonomy/blob/main/getting_started/1_annotation_tutorial.md)。
- 通过每种手、每种抓取类型的人工模板，合成接触丰富的抓姿；已有 MuJoCo 实现。
- 自定义手需要 MJCF、基础配置、手部接触分组、关节姿态与接触点/法向模板，以及碰撞骨架。不是只替换 URDF。
- 仓库列出的现成手包括 Shadow、Allegro、Leap、MANO、Unitree_G1；未列出 FDH-6。
- 标准流程使用预处理物体资产，适合离线生成抓取数据；不能直接把它称为原生 RGB-D 的实时抓取模型。
- 官方可选 BODex 接近轨迹示例目前明确只提供 UR10e + Shadow，因此 GR3 手臂仍需适配。

### BODex（ICRA 2025）

[官方仓库](https://github.com/JYChen18/BODex)以双层优化合成抓取，并提供 pre-grasp、grasp、squeeze 配置及部分机械臂接近轨迹。作者在 2026 年 4 月的仓库说明中推荐后续 Dexonomy，称其更易定制、合成结果更好。对我们而言，宜优先检查 Dexonomy，而不是直接替换已有 cuRobo V2。两者的环境和接口兼容性需要单独验证。

## 2. 从几何或点云生成完整手型

### DexGraspNet 2.0（CoRL 2024）

[项目主页](https://pku-epic.github.io/DexGraspNet2.0/)、[官方代码](https://github.com/PKU-EPIC/DexGraspNet2)。在大量合成杂乱场景中学习两阶段抓取生成，使用局部几何条件的扩散模型，并针对真实深度输入采用测试时深度恢复。官方展示了真实单视角深度条件下的生成和执行，适合参考“相机点云到完整灵巧手抓姿”的系统设计。官方评估代码依赖 Isaac Gym；FDH-6 的数据、模型输出和验证环境仍须适配。

### DexGrasp Anything（CVPR 2025 Highlight）

[项目主页](https://dexgraspanything.github.io/)、[官方代码](https://github.com/4DVLab/DexGrasp-Anything)、[论文](https://openaccess.thecvf.com/content/CVPR2025/papers/Zhong_DexGrasp_Anything_Towards_Universal_Robotic_Dexterous_Grasping_with_Physics_Awareness_CVPR_2025_paper.pdf)。生成整只手的姿态，并在扩散训练/采样中加入物理约束。论文与现成验证代码主要围绕 ShadowHand；不能把现成输出直接转成 FDH-6 六维手指控制。官方项目页还区分了手动移动全局手位姿与用 IK 自动规划的实验，说明“生成稳定抓姿”和“完整自主执行”需要分别检查。

## 3. 跨手型的手物交互表示

### D(R,O) Grasp（ICRA 2025）

[官方仓库](https://github.com/zhenyuwei2003/DRO-Grasp)、[论文](https://arxiv.org/abs/2410.01702)。输入包括机器人手的结构描述和物体点云，通过统一的手物交互表示生成抓取，适合研究跨手型适配。

官方提供权重、数据和新手型接入步骤：处理 URDF、采样手部连杆点云、标注运动方向等；最后一步明确要求使用自己的抓取数据进行预训练和训练。`object_pc_type` 提供 `partial` 选项，训练与验证配置应一致。它比夹爪位姿刚体映射更贴近我们的需求，但并不承诺任意新 URDF 都能直接使用现成权重。官方 Isaac Gym 验证为可选组件，是否改接我们现有 MuJoCo 验收需实测。

### DexGrasp-Zero（RSS 2026）

[官方仓库](https://github.com/YliangWu/DexGrasp-Zero-code)、[论文](https://www.roboticsproceedings.org/rss22/p122.pdf)。以统一语义动作空间和图状态表示训练跨手型强化学习策略。仓库提供多手模型文件及跨手测试示例；现成系统基于 GraspXL/RaiSim，包含 RaiSim 授权和环境依赖。对新的 FDH-6 仍需接入运动学与动作映射，不能把论文的跨手测试结论外推为已支持 FDH-6。

## 4. 连续闭环动作：强化学习和模仿学习

### NVIDIA DextrAH / DextrAH-G

[官方代码](https://github.com/NVlabs/DEXTRAH)、[DextrAH-G 论文](https://arxiv.org/abs/2407.02274)。在仿真中训练使用特权状态的强化学习教师，再蒸馏为相机输入的学生策略，结合 geometric fabrics 控制机械臂与手。现有 Isaac Lab 任务为 KUKA + Allegro，并提供控制、状态机和相机标定参考脚本；部分真机 ROS 2 驱动不包含在仓库里。

这条路线更接近持续观察和控制的抓取系统，但需要为 GR3 + FDH-6 重新定义动作空间、控制器、任务和训练分布。训练教师可以使用仿真状态；部署学生须明确限制为实际可获得的相机与关节观测。

### DexGraspVLA（AAAI 2026 Oral）

[官方代码](https://github.com/Psi-Robot/DexGraspVLA)、[项目主页](https://dexgraspvla.github.io/)。采用高层视觉语言规划和低层 diffusion policy，连续生成机械臂与手动作。公开数据格式为 13 维动作/状态，配头部图像掩码和腕部图像；发布了控制器权重与少量示例数据，但硬件相关代码并非全部开放。

它说明六自由度手也可以使用学习策略完成抓取；“动作维数相同”不意味着其预训练模型适用于 FDH-6。机器人运动学、相机配置、手指作用和演示分布都不同，需重新采集/适配 GR3 数据。

### DexUMI（CoRL 2025）

[官方代码](https://github.com/real-stanford/DexUMI)、[项目主页](https://dex-umi.github.io/)。通过人手操作接口与外骨骼采集演示，处理手型差异，再训练 diffusion policy；已有 Inspire 和 XHand 采集与部署流程，也包括可选的力传感输入。这条路线适合后续真机示教和接触控制，现阶段需要额外的数据采集工作，不能替代 FDH-6 的运动学和控制标定。

## 对当前项目的建议

以下是基于代码接口、现有 MuJoCo/cuRobo 栈和 FDH-6 结构作出的工程判断，不是已验证的性能结论。

1. 先以 Dexonomy 的方法为参考，建立 FDH-6 接触模板：从侧向包络、拇指对向捏取、适用的斜向抓取开始，优化手腕与六个主动关节。保持五个联动关系与当前的物理验收标准。
2. 用现有扫描 mesh 离线合成与验证 FDH-6 抓姿，确认哪些物体/手型在物理上能抓住，并生成训练数据。这一步只验证合成和手的抓取能力，不算相机自主抓取。
3. 在线继续使用头部 RGB-D 与多视角融合；参考 D(R,O) Grasp 或手型专用生成模型，从部分点云产生完整抓姿，或对重建形状做接触优化。不可把仿真真值 mesh/位姿直接当作在线观测。
4. 保留 cuRobo 作为手臂运动规划器，补齐预成形、允许接触的接近、闭手、接触确认、提起和保持的执行逻辑。手指配置改变后，路径中的手部碰撞几何也需要更新。
5. 若上述阶段仍无法可靠执行，再引入 DextrAH 式强化学习/视觉蒸馏，或 DexGraspVLA、DexUMI 式示教策略；这样可以先明确失败来自几何可行性、感知还是控制。

我核对的上述项目没有列出可直接用于本项目 FDH-6 的现成配置与权重。优先级建议为：Dexonomy 的接触/手型合成 → 部分点云条件生成 → 完整闭环执行。论文报告的成功率使用不同手、物体、初始化与验收条件，不应当作 GR3 + FDH-6 的预期成功率。
