# 实物扫描资产与 M2T2

2026-10-20，当前服务器完成验证。“实物”在此指真实物体扫描得到的三维资产；物理运动发生在 MuJoCo，尚未连接真机。

本文的单例数据为初始验证记录。后续增加十物体测试、头部多视角融合，并修正 M2T2 上游目标掩码筛选的括号错误；当前默认启用该修正。复现旧筛选行为需加 `--legacy-m2t2-filter`。详见 [头部扫描与点云融合](头部扫描与点云融合.md)。

## 复现

```bash
cd gr3_grasping
python3 scripts/fetch_assets.py
uv sync --locked --extra dev --extra perception --extra m2t2
.venv/bin/python scripts/fetch_m2t2_weights.py
.venv/bin/gr3-grasp simulate --config configs/scanned_candy.yaml \
  --backend m2t2 --output outputs/my_scanned_candy
```

成功回放已保存在 `outputs/scanned_candy_m2t2_video/grasp.mp4`；快速验证结果在 `outputs/scanned_candy_m2t2`。`--no-video` 可跳过逐帧软件渲染，不改变物理执行。

不闭手对照应返回退出码 1，报告 `grasp_executed=true`、`grasp_success=false`：

```bash
.venv/bin/gr3-grasp simulate --config configs/scanned_candy.yaml \
  --backend m2t2 --no-close --no-video --output outputs/my_no_close
```

药瓶尝试亦未通过，保留真实失败：

```bash
.venv/bin/gr3-grasp simulate --config configs/scanned.yaml \
  --backend m2t2 --no-video --output outputs/my_bottle
```

## 位姿与手部映射

官方源代码：[NVlabs/M2T2](https://github.com/NVlabs/M2T2)，提交 `be2e5f6feae2f961615ab0f7b643f0f98b0c3a50`。权重：[作者 Hugging Face 仓库](https://huggingface.co/wentao-yuan/m2t2)，修订 `a20325dcd19cd1b838274974d0ebe35bfe383796`，文件 SHA-256：`e35c3cb11e06f46c5d406bdfc756bc06f48b256dd6d638408d9a5ff13deb97fb`。下载和默认加载均检查校验值。

推理保留完整官方网络、严格加载全部参数、使用原始 16384 场景点配置，输入仅来自 RGB-D 反投影。点云包含观测桌面和物体，将配置的桌面原点平移到模型坐标系，输出再平移回世界。网络输入特征按官方预处理减去点云均值，不对输出重复去中心。

由于显存被既有任务占用，本项目以 `pointnet_cpu.py` 显式实现推理用 FPS、球查询、分组和三点插值，网络在 CPU 运行。已测试邻域顺序、半径边界、填充、距离和插值；未做 CUDA 输出逐位一致性比较。FPS 距离并列时可选到不同点，CPU 算子不用于训练。

M2T2 输出源夹爪基座位姿。按其 `action_decoder.build_6d_grasp` 中的 **0.1034 m** 深度转换为接触中心，不能套用 GraspGen 的 0.10527314 m。源夹爪的 Z 是接近轴、X 是闭合轴；现有 FDH-6 手部 site 的 X 指向手掌开口、Z 指向拇指/其他手指对向区域，因此需换轴，而不是直接复制旋转矩阵。允许交换两侧夹爪的对称候选。

`fdh6_contact_offset_m: [-0.012, 0, -0.045]` 表示接触中心相对现有手部 site 的仿真估计偏移，根据手的仿真接触区域设置；这仍不是实机标定。左手镜像分支尚未通过本组扫描物体的完整抓取验证。保留模型预测的接触中心，不读取目标真值来改写候选位置。

糖果盒案例的模型输出 651 个原始接触候选，按选中点云和相邻位姿去重保留 24 个，再生成两侧闭合对称候选。第 0 个映射候选通过规划并成功抓取。模型约 1 秒完成推理，不含加载、渲染和机械动作；这是该服务器单场景耗时，不是速度基准。模型分数是接触置信度，未经 FDH-6 成功概率校准，`fdh6_quality_validated=false` 指该模型没有经过本手型的通用质量验证。单次物理执行成功单独记录在 `report.json`。

## 结果与限制

| 实验 | 保持期最小升高 | 保持期 | 对向承力接触比例 | 最大手指穿透 | 判定 |
|---|---|---|---|---|---|
| 扫描糖果盒，M2T2 + FDH-6 | 14.60 cm | 2 s | 99% | 2.03 mm | 成功 |
| 同预测/轨迹，不闭手 | 约 0 cm | 2 s | 0% | 0 mm | 失败，符合预期 |
| 扫描药瓶，M2T2 + FDH-6 | 未形成稳定提起 | 2 s | 0% | 约 1.69 mm | 失败；闭手拨倒物体 |

物体保留自由关节与正常重力，32 个凸部件分别参与接触，无物体 weld、吸附或位姿强制设置。物体真值仅用于接触允许列表、目标关联和成功评估；环境碰撞仍使用已知仿真几何，尚未实现从实测场景点云重建所有障碍物。固定基座、理想重力补偿、假设相机内参和手部参数仍限制迁移。

逐候选离线评估：

```bash
.venv/bin/python scripts/evaluate_candidates.py outputs/scanned_candy_m2t2 \
  --output outputs/my_candidate_trials --limit 12 --stop-on-success
```

每次从相同初始仿真场景独立运行，并记录每个候选的轨迹、接触和高度；这不是实机自动重抓控制器。`--candidate-index N` 可在 `gr3-grasp simulate` 中单独复现某个映射候选。药瓶已保存前 24 个映射候选的失败汇总：`outputs/scanned_m2t2_sweep/summary.json`。

## 换成其他扫描物体

将上游物体目录加入稀疏检出后，在 YAML 的 `scene.objects` 中添加：

```yaml
- name: my_object
  type: mjcf
  mjcf: third_party/mujoco_scanned_objects/models/<物体目录>/model.xml
  placement_xy: [0.46, -0.20]
  rotation_rpy_deg: [0, 0, 0]
  mass: 0.10
```

导入器会为 mesh/material/texture 加独立前缀，解析绝对资源路径，按网格真实底部放到桌面上，并缩放源估算惯量以匹配显式质量。当前支持 GSO 这种单刚体、无关节、无自定义默认类的模型；复杂 YCB/其他 MJCF 需要单独核对，不能据此假定任意 XML 都兼容。杯子已下载，但尚未完成导入和抓取验证。所有新增物体仍需重新评估位姿、预成形和实际接触，不能沿用单例成功率。
